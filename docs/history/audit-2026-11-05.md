# GHOST audit — 2026-11-05

Historical snapshot against the baseline below. File paths and failed checker
experiments describe that state, not the current repository. Current unfinished
actions belong in the [checklist](../planning/checklist.md). The old Python
checker and its expansion proposals have been retired.

Baseline: `6ad5f086dd20e460de1767547b46fe3538021452`, freshly cloned from
`git@github.com:nikkeyl/ghost.git`. The initial worktree was clean. Scope:
repository structure, instructions, capability routing, roadmap accuracy, the
existing validation command, and available evidence about the author's needs.
This is a documentation/capability audit, not a security scan or six-host trial.

## Assessment

The core is coherent: source-of-truth separation, scoped changes, explicit
uncertainty, native frontend contracts, progressive loading and proportional
verification are already represented. The highest-value work is stronger
evidence and platform-depth learning, followed by capabilities justified by real
tasks. Catalog size is not a measure of engineering judgment.

Observed inventory: 6 rules, 16 knowledge documents, 19 active skills, 13
passive detectors and 8 templates. All 32 skills are represented in the index. A
focused inspection found the expected headings in every active skill and
resolved all 79 graph relations against skills and knowledge documents. This
inspection was a one-off audit check; it is not implemented in the current CI
checker.

## Discriminating checks

The unmodified command `python3 utilities/check-docs.py` passes for 32 skills.
Each mutation below was applied to a separate disposable copy, never to the
working repository. The same command returned exit code 0 for all five:

| Mutation                                              | File                       | Actual result |
| ----------------------------------------------------- | -------------------------- | ------------- |
| Replace mandatory `## Verification` with `## Omitted` | `verify-change/SKILL.md`   | Accepted      |
| Replace prerequisite with `nonexistent-skill`         | `verify-change/SKILL.md`   | Accepted      |
| Remove the skill's identifier from the catalog        | `.agents/skills/README.md` | Accepted      |
| Replace the backlog link with `./does-not-exist.md`   | `docs/ROADMAP.md`          | Accepted      |
| Give `verify-change` the name `understand-codebase`   | `verify-change/SKILL.md`   | Accepted      |

The script uses a regex to collect fields, so it also does not establish
complete YAML validity. Earlier import documentation records richer one-off
checks; that historical inspection is not evidence that today's CI enforces the
same contracts.

No assertion is made that these five defects currently exist in the unmodified
catalog. The experiment establishes detection gaps, not existing broken skills.

## Acceptance and limits

This audit uses static inspection and temporary-copy checker experiments. It
does not establish skill outcome quality, independent human proficiency, current
npm package defects, deployed OAuth acceptance, or discovery on any target
runtime. The source article/gist fetch attempts were unsuccessful, so article
descriptions are attributed to the checked-in analysis. Personal material was
summarized only where relevant to engineering; raw personal records were not
imported.

See [the checklist](../planning/checklist.md) for acceptance conditions and
[the profile](../reference/author-profile.md) for provenance and learning
priorities.

The Python checker and archive utilities described in this historical audit were
subsequently removed at the author's request. Current CI uses separate
EditorConfig, Prettier and remark workflows; releases use Git and GitHub
directly. The checker expansion proposals above are superseded by the current
[checklist](../planning/checklist.md).
