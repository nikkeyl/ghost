# Implementation plan

## Contract and baseline

Summarize the settled requirements, repository state, scope, and exclusions.
Include enough context for a fresh session to proceed without the conversation.

## Decisions and affected boundaries

Name the selected approach, owner, alternatives, material trade-offs, risks,
and any recovery needs. Keep requirement changes explicit.

## Work units

| Unit | Outcome and paths | Dependencies | Verification | Status |
|---|---|---|---|---|

Choose units that leave the relevant system runnable and reviewable. Each
should have a concrete completion condition; checkpoints do not imply commits.

## Completion and handoff

Map final evidence to acceptance criteria. Record deviations, open risks,
and the next authorized step. Follow the adopting project's planning location.
