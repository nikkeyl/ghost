# Task requirements

## Outcome and scope

State the problem, required behavior, consumers, constraints, and
non-goals.

## Verified context

Record the relevant state/date, owners, contracts, existing analogues,
and evidence. Facts describe the current system; they are not
implementation steps.

## Requirements and invariants

| ID | Observable requirement | Source or rationale | Verification |
| -- | ---------------------- | ------------------- | ------------ |

## Decisions and open questions

Record settled choices, assumptions, and source contradictions.
Distinguish questions that block implementation from justified
non-blocking defaults.

## Acceptance criteria

Use a flat checklist of observable outcomes. Include the relevant error
and edge behavior; do not invent adjacent requirements from related
tickets.
